## Gate status and acceptance evidence

### G0 — First legitimate receiving path (OPEN)
Verify an accessible, lawful, no-upfront-cost way to receive funding. Private identity, payout, tax and account verification must be completed by the owner directly. Do not publish payment credentials or recovery information.

### G1 — First cash flow independent of Mainnet (OPEN)
Prepare a concrete offer for demonstrated Rust/protocol, reproducibility, developer tooling, or AI/ML work. Each offer needs a scope, deliverable, timeline, acceptance tests, support boundary, and written payment terms. A public call or proposed token allocation is not received revenue.

### G2 — Canonical Genesis and monetary accounting (OPEN / CRITICAL BLOCKER)
Freeze one versioned network/Genesis profile and exact reward, fee, halving, difficulty and supply rules. Integrate/enforce them in production, validation/import, fork choice/reorg, storage, replay, snapshots and state roots. Prove exact-cap boundaries and accounting through clean-checkout tests, independent vectors/reference logic and cross-client agreement. One successful transaction cannot close this gate.

### G8 — Independent anti-rollback trust and recovery (OPEN)
Integrate an independent monotonic trust/CAS domain outside the node restore boundary; qualify stale restores, concurrency and storage/device failures on separate hosts.

### G12 — Native EVM/RPC for the planned EVM-capable launch (OPEN)
Integrate VM rules, gas, account/code/storage, receipts/logs and rollback into the canonical node; prove deploy/call and matching results across independently built nodes.

### G13 — Public zero-value devnet (OPEN)
Run multiple independently operated nodes; provide native wallet, RPC, explorer/indexer, sync and recovery guidance; publish only authentic telemetry with commit, configuration, hardware, test window and raw outputs.

### G14 — Release, independent review, and jurisdiction-specific compliance (OPEN)
Reproduce builds, review provenance/SBOM, obtain independent protocol/cryptography review using funded or genuinely voluntary resources, check name/ticker conflicts, and assess requirements for the actual launch jurisdictions and distribution structure.

### G15 — Real trading and liquidity (OPEN)
Use only an actual supported production asset path with legitimate counterparties, paired asset, valid buy/sell access, and verifiable market/pool data. Native coin units alone do not create external purchasing power or meaningful pool depth.

### G16 — Platform data (OPEN)
Assess CoinMarketCap, CoinGecko, DEX Screener, TradingView, wallets and data APIs independently after their own prerequisites pass. Save official responses and direct URLs; never guarantee listings or universal coverage.

## Transaction cost: what can and cannot be done for USD 0
- Local unit/integration tests and a simulated ledger transaction can cost **USD 0**. They are not production transactions.
- A public testnet transaction can often use test tokens from a faucet at no token purchase cost; those assets have no intended market value and do not establish a native QZXB Mainnet.
- At present, no production native QZXB network is evidenced, so there is no legitimate native-Mainnet transaction to send.
- Gate 2 is a protocol integration/accounting gate, not a minimum-fee transaction gate. It requires the full acceptance evidence above.
- A real transaction on another production chain requires its network's gas asset; fees fluctuate. Deploying another ERC-20 would create a different asset, not finish native QZXB.
- A real DEX market additionally needs an actual paired asset and legitimate liquidity. Never add liquidity, move funds, or deploy a value-bearing contract without the required authorization.

## Giveth donation route: eligibility gate FIRST
Giveth describes project creation and donations as zero-platform-fee and supports selected chains including Ethereum Mainnet, Gnosis, Arbitrum, Base, Polygon, Celo, Optimism, Solana, Stellar and Ethereum Classic. Token choices vary by chain/project, and Bitcoin mainnet is not listed as a supported donation network in its current donor guide. The live interface should be checked for exact token availability; never assume USDT is enabled on every supported chain. Use a wallet address the owner controls, not an exchange deposit address.

**Important eligibility condition:** Giveth's Terms of Use, published as October 2026, include restrictions tied to sanctions/jurisdiction and expressly prohibit using a VPN or other technical means to disguise geographical location. If actual residence and VPN exit location differ, do not use the VPN to bypass access or eligibility controls. Seek written guidance from official Giveth support using truthful facts before any onboarding. A project setting such as “global impact” describes the project's impact, not the founder's eligibility to use the platform.

Giveth's verified/public-good programme also says projects focused on personal gain are not eligible for its GIVbacks status and prohibits promising tokens or other goods/services in exchange for donations. Any possible campaign must truthfully describe a public-good scope, intended use of funds, and progress reporting without token-return promises. Donations are not assured.

**Wallet security:** Do not give ChatGPT a seed phrase/private key or ask it to custody/send funds. A public recipient address is not a secret, but the owner should enter and verify it directly in the chosen platform only after eligibility is confirmed. Never send funds to a guessed address.
