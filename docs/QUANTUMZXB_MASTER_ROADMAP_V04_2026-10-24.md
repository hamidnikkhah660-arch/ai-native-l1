### CP-0391–CP-0410: candidate protocol surfaces

- v0.4 allocation/Genesis/ledger candidates bind policy and state-root data, but do not by themselves establish that the canonical producer/importer uses the profile.
- CP-0403/0404 add a profile-bound QZB4 v2 transaction-bearing candidate and candidate snapshot/dispatch path. The test authenticator and configured subsidy schedules remain test inputs, not approved Mainnet economics.
- CP-0405 adds the QZBE envelope and an in-memory bounded branch graph. The CI run for SHA `f201b2d4f510cf7bd881c064012307c76b317456` passed; the candidate is still not wired into canonical node listeners/import or production storage.
- CP-0406 adds a local-only persistent QZBE branch archive with immutable numbered manifests, digest-named branches, manifest/profile checks, rejection of non-regular manifest/branch paths, and full Genesis replay during reopen. Its focused test command is `cargo test --locked --offline --lib monetary_pow_v04_store_candidate -- --nocapture`; **7 passed, 0 failed**. The final local `cargo test --all-targets --locked --offline` exited 0; the library harness reported **823 passed, 0 failed**, and both `devnet_node` and `private_testnet_node` test harnesses reported **36 passed, 0 failed** each, with all remaining targets passing. `cargo fmt --all -- --check`, `cargo check --all-targets --locked --offline`, release checksum rebuild (376 entries) and public docs preflight (47 README-relative links) also passed. GitHub Actions run `40112877967` passed on the exact CP-0406 SHA `80935c27a4c7da22492cf6fa8b8ad39148d5a395`, with both jobs successful. CP-0407 was subsequently validated on its exact implementation SHA by GitHub Actions run 40122352670; CP-0408 is a further offline-only candidate executable and requires its own full validation/CI before promotion.

- CP-0407 extends the QZBE store with candidate APIs for exact-manifest commitments, pinned signed anchor reads, conditional exact-successor CAS writes, and pending-manifest recovery after either CAS conflict or a lost response. The in-memory provider fixture is test-only. No concrete cloud/provider adapter or independent operator deployment exists. A checksummed local QZCA mode marker now prevents accidental plain-submit after CAS setup and rejects marker corruption; it is only an operational guard because it remains locally mutable/deletable, not an anti-rollback trust anchor. The focused candidate test suite reports **10 passed, 0 failed**. Follow-up hardening now persists QZCA mode before the first provider read, checks pending-CAS state only after acquiring the OS writer lock, and validates plain-reopen fail-closed behavior; the CP-0404 temp-path fixture now adds a high-resolution timestamp to prevent PID reuse collisions. On this working tree the complete `cargo test --all-targets --locked --offline` run passed (826 library tests, both node suites 36/36, smoke binary 6/6, all remaining targets successful), as did format and `cargo check --all-targets`. After the hardening follow-up, the full local all-target suite/check and formatting passed, and GitHub Actions run `40139044429` passed on exact source SHA `beb531ecd2ef23ba09c5e113bb2cd1e6a4661a03`: both `Format, check, and test` and `Windows PMT4 TXN4 two-node loopback` are green. The prior checksum/doc preflight reported 379 entries / 49 README-relative links; the new CP-0409 brief and README/roadmap links are being incorporated into a documentation-only follow-up with a fresh checksum rebuild and CI run. None of these results imply independent provider deployment or Gate 8 closure.

- CP-0410 corrects QZBE consensus identity: the v2 envelope's proof/fork-choice digest binds the full canonical QZB4 v2 body ID, not only the PoW header. A regression test constructs two bodies with equal headers/state roots but different body IDs, confirms the legacy header-only digests collide, and verifies distinct QZBE v2 identities and deterministic replay. The QZBE envelope, PoW fingerprint, QZMF manifest, QZCA local marker, and CAS operation domains use versioned V2 domains. Focused candidate/store tests pass (4/4 and 11/11); format, all-target check and the complete all-target test suite also pass locally (828 library tests, both node suites 36/36, QZBE smoke 6/6, all other targets green). Offline smoke replay and public docs preflight pass (381 checksums, 51 README-relative links). Fresh CI is the next gate. This is a local candidate correction, not canonical-node integration or an independent audit.
- CP-0411 adds a bounded body-aware QZBE v2 miner candidate. Each call accepts 1-256 attempts, checks a cancellation callback before each memory-hard hash, advances the nonce with checked arithmetic, and tests the final body-bound digest against the selected parent target. A valid candidate is re-verified but not inserted until ordinary submission. The offline smoke uses an easy non-MAX target. Focused tests pass; the full local suite passes with 830 library tests, both node suites 36/36, smoke 6/6 and all other targets green. Manual persistence/restart smoke passed from height 0 to 3, then after reopen from 3 to 5. Fresh CI is pending; canonical-node integration and production readiness remain open.

- **CP-0413 authenticated QZBE runtime loopback:** a separate binary accepts only loopback binds/peers, explicit test Genesis/schedule, one pinned Noise peer and dedicated local QZBE storage; it rejects transactions, uses an easy local PoW profile, propagates blocks with state/tip-bound ACKs and verifies restart/replay equality. Local Windows release two-node integration passes at height 2 with public-bind denial; targeted node and Noise tests pass. This is not canonical-node wiring or production security evidence.
- **CP-0414 authenticated QZBE transfer:** extends the isolated runner to a single explicit Ed25519 public-key registry; its Windows release scenario rejects a valid-PoW block with a tampered transaction signature without changing the receiver snapshot, then accepts a correctly signed 2,500-atom transfer. Independent nodes replay height 2 to the same state root/tip and recipient balance. Local scenario and full locked/offline all-target suite passed; exact-head CI [40278927677](https://github.com/hamidnikkhah660-arch/ai-native-l1/actions/runs/40278927677) passed both jobs for `dc39c3f`. Still not canonical runtime, not a public service and not launch authorization. Exact-head CI and full locked/offline all-target validation passed for CP-0414; Gates 2/8/13/14 remain open.
- **CP-0415 explicit QZBE entrypoint dispatch:** `devnet_node --qzbe-v04-peer-smoke` routes through the Devnet executable into the isolated QZBE runtime only when the exact leading subcommand is present. The Windows release integration passed with a signed 2,500-atom transfer, atomic rejection of a valid-PoW/tampered-signature block, matched height-2 root/tip/balance after replay, and public bind denial. Local all-target and Windows integration passed; exact-head CI [40281745961](https://github.com/hamidnikkhah660-arch/ai-native-l1/actions/runs/40281745961) passed both jobs for `d9b1635`. This remains entrypoint wiring only; QZBE producer/importer and fork-choice are still separate from canonical PTB2/PFS2 and PMT4/PFM4 state machines.
- **CP-0416 immutable profile lock / downgrade guard:** QZBE creates a create-once, fixed-width `qzbe-runtime.profile` marker binding network ID, Genesis manifest, QZBE profile and consensus parameter fingerprint. Corrupt/mismatched markers and existing QZBE artifacts without a marker fail closed; the default legacy `devnet_node` route refuses any data directory containing the marker instead of silently reinterpreting or downgrading the store. The complete locked/offline all-target suite passed (831 library tests, `devnet_node` 45/45, private node 39/39, QZBE smoke 6/6 and profile-lock runtime 5/5). Windows release integration also passed with the actual `devnet_node.exe` dispatch, signed transfer, atomic bad-signature rejection, replay and legacy-downgrade refusal. Exact-head CI run [40283401837](https://github.com/hamidnikkhah660-arch/ai-native-l1/actions/runs/40283401837) passed both jobs for commit `cecf3bd`. The unkeyed marker detects accidental/corrupt profile changes but is not independent anti-rollback protection; Gates 2/8/12/13/14 remain open.
- **CP-0417 explicit canonical family-dispatch contract:** added a candidate-only `canonical_version_dispatch_candidate` module requiring an explicit activation schedule and per-epoch network/Genesis/profile pins. It selects exactly one expected family by height and wire magic, rejects wrong-family inputs without fallback, rejects inner QZB4 bodies/snapshots on the block-envelope route, and supports post-decode identity checking. Focused tests pass 7/7 locally. It is not yet wired to the node, and no production activation height/economic profile was chosen; Gates 2/8/12/13/14 remain open.

Neither CP-0406 local storage nor CP-0407's injected CAS contract itself proves production anti-rollback resistance. The complete node directory remains mutable, the provider is still only an interface/test fixture, and external object-generation floors must be protected outside the node rollback domain. Do not describe this as Gate 8 closure or wire it to production-value state without independent qualification.

## Execution plan — no owner-funded spend

1. **CP-0410 QZBE v2 correction - local tests green; fresh CI and independent review remain open.** Format/check and all-target suite passed locally: 828 library tests, both node harnesses 36/36, QZBE smoke 6/6, all other targets green. The offline persistence/replay smoke advanced from height 0 to 3, reopened, and resumed from height 3 to 5; the 381-entry/51-link docs preflight passed. The external CAS provider remains a test fixture; Gate 2 and Gate 8 remain open.
2. **Publish a reviewable candidate commit.** Keep CP-0413 runtime, CP-0414 signed transaction, CP-0415 Devnet entrypoint dispatch and CP-0416 profile-lock hardening on isolated stacked Draft PRs; do not alter earlier PRs or merge on green CI alone. Require fresh all-target validation, the Windows adversarial transaction/profile-lock scenario and independent design/security review on the exact candidate SHA.
3. **Finish canonical monetary integration (Gate 2).** Trace actual producer/import/state-transition/fork-choice/store/replay/RPC call sites. Define and approve the complete schedule and activation/migration rules before selecting parameters. Implement one versioned transition and prove exact-cap/cap+1, reward boundary, wrong-profile, forged reward, duplicate/replay, overflow, reorg and restart behavior with independent vectors.
4. **Integrate a genuinely independent CAS provider (Gate 8).** Reuse audited provider protocol types where appropriate, but select and operate a provider only after ownership, key custody, provider administration, recovery responsibility and acceptance tests are explicit. The mock/in-memory provider in tests cannot be the production trust anchor.
5. **Qualify a public zero-value devnet.** Define a reproducible operator package, use independent operators/hosts, test network splits, mixed versions, replay, reorg, snapshot restore and incident recovery; publish only measured, source-attributed telemetry.
6. **Complete security/release qualification (Gate 14).** Independent reviewers evaluate the actual selected runtime, signing/authentication, economics, storage trust boundary and release supply chain. Resolve critical/high findings and publish scope/limitations clearly.
7. **Complete owner/jurisdiction review before an offer or value-bearing launch.** In the EU/Netherlands, determine the precise MiCAR classification, issuer/offer/admission model, white-paper obligations and any CASP obligations with qualified counsel and relevant authorities. A white-paper notification is not regulatory approval. The owner must separately finish private payout/tax/accounting steps; these should not be placed in a public issue or repository.
8. **Launch the native asset only after explicit go/no-go.** Publish the exact selected source/release SHA, Genesis and supply methodology, node/wallet/RPC/explorer endpoints, operator/security evidence, incident contacts and real distribution rules. Mainnet activation, mint/distribution, signing keys and any value-bearing transactions require explicit owner authorization after the technical and legal prerequisites pass.
9. **Create actual market access, then apply for data coverage.** Choose either a genuine native-chain exchange integration or a separately reviewed DEX/bridge path with a real quote asset. Publish no price, circulating supply, liquidity or volume claim until authenticated, inspectable source data exists.
