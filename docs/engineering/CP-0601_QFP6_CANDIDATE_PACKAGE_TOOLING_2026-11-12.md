# CP-0601 - QFP6 candidate package scaffold and canonical identity validator

**Date:** 2026-11-12
**Status:** Candidate tooling only; no Genesis or Mainnet authorization.
**Base:** CP-0600 / `6535627`.

## Implemented in this worktree

- `tools/qfp6_candidate_package.py` creates a deterministic package directory structure and a versioned `qfp6-candidate-package/v1` manifest.
- The manifest explicitly records QZXB/QFP6 identity, candidate-only release channel, missing artifact states, independent-review gates, signing/trust-floor state, and runtime qualification state.
- The package tool validates every supplied artifact's SHA-256, rejects paths escaping the package root, rejects malformed pins and refuses to label an incomplete package ready.
- `qfp6_candidate_validate` is a Rust binary using the repository's existing canonical Q6GD and Q6CP codecs. It requires separately supplied Q6GD and Q6CP SHA-256 pins, decodes both artifacts, and validates their network/profile/Genesis-commitment/consensus-fingerprint binding. It never creates or signs trust material.
- An initial scaffold is stored at `release/qfp6-candidate/`.

## Local use

```powershell
python tools/qfp6_candidate_package.py init release/qfp6-candidate
python tools/qfp6_candidate_package.py validate release/qfp6-candidate
python tools/qfp6_candidate_package.py self-test

cargo run --manifest-path src/native/pow_bench/Cargo.toml --locked --offline --bin qfp6_candidate_validate -- `
  --q6gd release/qfp6-candidate/artifacts/genesis.q6gd `
  --q6gd-sha256 <independently-pinned-q6gd-sha256> `
  --q6cp release/qfp6-candidate/artifacts/consensus.q6cp `
  --q6cp-sha256 <independently-pinned-q6cp-sha256>
```

The validator deliberately fails until actual canonical Q6GD/Q6CP files and independently obtained digest pins are supplied.

## Explicit limitations

- The initial package is intentionally incomplete: no Genesis snapshot, Q6GD, Q6CP, Q6PN, Q6TS, or bootstrap peer set has been fabricated.
- The Rust validator validates Q6GD/Q6CP binary structure and binding; Q6PN/Q6TS cryptographic signature and anti-rollback qualification remains a separate gate.
- This work does not connect `qrun_v06_node --run` to the permissionless base runtime. That requires the CP-0588 base-runtime constructor, Genesis replay, time/retarget policy, durable fork-store and fork-choice integration, transaction ingress, listener, mining lifecycle and restart/reorg tests.
- Existing SHA-256d easy-fixture parameters remain candidate-only. They are not calibrated Mainnet parameters.
- Founder account remains unset until the owner creates and verifies a local wallet address. No secret material is requested or stored.
- Public Q6TS signing requires independently controlled reference keys and trust-floor infrastructure. No private signing key is generated by this tooling.

## Verification required before commit

- Python package-tool self-test (incomplete package must fail closed).
- Rust `cargo check --locked --offline --bin qfp6_candidate_validate`.
- `rustfmt --check` for the new binary and `git diff --check`.

## No-go boundary

This candidate package is not a production release, does not enable public mining, does not issue QZXB, does not start a public listener, and does not create a QZXB/USDT market or settlement route.
