# CP-0464 — QRun / QZXB Brand Identity
Date: 2026-10-29

Status: **Founder-selected naming direction recorded.** This is a project naming decision, not a trademark clearance, exchange listing, Mainnet activation, or claim of market value.

## 1. Canonical public identity

- **Brand / spoken coin name:** QRun.
- **Native coin ticker:** QZXB.
- **Network name:** QRun Blockchain.
- **Acronym expansion:** Quantum Zeta eXecution Blockchain.
- **Letter mapping:** Q = Quantum; Z = Zeta; X = eXecution; B = Blockchain.
- **Ticker pronunciation:** Q-Z-X-B (read the four letters, not as a word).
- **Short public usage:** “I bought QRun”; “QRun price”; “QRun Blockchain”; symbol/code shown as QZXB.

QRun is the short name people should remember and say. QZXB is the ticker/technical symbol used in wallets, node outputs, source code, transaction/accounting data, and any future market-data integration. The network name is QRun Blockchain. The expanded phrase explains the symbol; it does not replace the short brand in everyday speech.

## 2. Consistent writing

Use **QRun** for the brand, **QZXB** for the native coin ticker, and **QRun Blockchain** for the network. Spell the acronym expansion exactly as **Quantum Zeta eXecution Blockchain** when the expanded phrase is needed.

Examples:
- “QRun is building an independent Layer-1 blockchain.”
- “QRun Blockchain is the native network.”
- “QZXB is the native coin ticker.”
- “QRun, native coin ticker QZXB.”

Do not call the native coin “Qanvoryx” or “QX”: those labels belong to a separate historical EVM test-asset experiment and must not be confused with the native coin. Do not describe QZXB as a listed ticker until a real listing has been verified.

## 3. Technical and monetary identity remain separate

This naming decision does not modify consensus or wallet derivation. The current QRun candidate identity, profile/Genesis commitments, owner account, 10B Genesis policy, fee-only block-production direction, and Mainnet release gates remain controlled by their respective versioned protocol records. Do not change network IDs or Genesis commitments merely to reflect a brand-wording change. The latest owner-directed monetary policy remains CP-0437: 10,000,000,000 QZXB at Genesis, zero subsequent minting, and zero block subsidy. A local candidate balance is not public Mainnet activation or proof of market value.

## 4. Brand-conflict and readiness note

A preliminary web search found a similarly named blockchain project, QRUNE, which publicly describes itself as a Layer-1 protocol and uses the QRUNE name/ticker. This is not, by itself, a conclusion of trademark infringement, unavailability, or legal conflict; however, the close visual/spoken resemblance is a real brand-confusion risk. See the [QRUNE project white paper](https://qrune.io/wp-content/uploads/2026/02/qrunewhitepaper.pdf).

Before major commercial promotion, domain acquisition, trademark registration, or exchange/listing applications, check the relevant trademark registers, domain availability, social handles, and naming conflicts in target jurisdictions. Until that diligence is completed, treat QRun / QZXB as the founder-selected project naming direction, not as a legally cleared mark. Do not change the founder's selected name automatically; report any verified conflict with evidence before suggesting a replacement.

## 5. Current operational disclosure

As of this date, the QRun/QZXB native node remains an experimental candidate: the live local node reports `mainnet=false`, height 0, and zero configured peers. No public QRun Mainnet, confirmed public price, QZXB/USDT pool, or public exchange listing is claimed by this branding decision. Keep all website, wallet, README and market statements aligned with that distinction.

## 6. Propagation scope

The current-facing README, homepage, wallet window, market-tool README and white-paper identity note were aligned with this decision. Filenames, Rust crate/bin names, wire protocol identifiers, historical documents, legacy EVM test-asset names and domain/contact endpoints are not automatically renamed because such changes may break paths or falsify history. They should be migrated only through explicit compatibility-safe work.
