# Draft inquiry — OSU Open Source Lab hosting eligibility

**Not sent.** This is a draft for the project owner to review and send if desired. It does not request provisioning or create an account.

To: info@osuosl.org  
Subject: Preliminary hosting eligibility inquiry — open-source Layer-1 test infrastructure

Hello OSU Open Source Lab team,

I maintain AI-NATIVE L1 / QRun, an experimental open-source Rust Layer-1 project licensed under Apache-2.0. The repository is public and the project is seeking independent review and operator participation.

Before submitting a full hosting request, I would like to ask whether a project at this stage could be considered under your hosting policy.

The potential request would be limited to a small Linux VM or equivalent infrastructure for a future **zero-value-only** public test environment. No real-value assets, financial services, mining payouts, token rewards, or Mainnet traffic would be involved. The service would remain experimental and subject to a documented security/release gate.

We understand from your hosting policy that you prioritize projects with significant positive impact and active development communities, and that you generally avoid hosting smaller projects that can remain on free services such as GitHub. We do not want to submit an unsuitable request or assume that infrastructure is available.

Could you advise, at a high level:

1. Whether an experimental Layer-1 protocol project with a public Apache-2.0 repository could be considered at all under the current policy.
2. Whether your hosting programme can support an independently administered Linux VM with stable public networking and inbound TCP.
3. Whether TPM2/vTPM or another host-bound credential mechanism is available or supported, or whether this would be outside your service model.
4. Whether there are minimum project maturity, community activity, usage, or infrastructure-scale thresholds we should meet before applying.
5. Whether any jurisdictional, institutional, or applicant eligibility restrictions should be checked before we submit a formal request.

We are not asking you to provision anything at this stage. We can provide the repository, current technical status, and a concise threat model if the project appears potentially eligible.

Thank you for your time.
