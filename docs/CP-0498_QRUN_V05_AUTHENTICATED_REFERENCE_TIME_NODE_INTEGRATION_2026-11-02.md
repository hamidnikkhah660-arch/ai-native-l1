# CP-0498 — QRun v0.5 authenticated reference-time node integration

Date: 2026-11-02

Status: **Implemented in the node runtime and CLI candidate; public-alpha now fails closed without a network-bound signed reference-time provider. Mainnet remains release-gated and its identity remains unfrozen.**

## Why this checkpoint exists

CP-0495/0496 added a two-sided live timestamp window and a committed Genesis epoch. The QRun node was still using its operating-system clock unconditionally, even though the repository already contained an authenticated RTP1/TMA1 reference-time provider. That left independent public nodes exposed to inconsistent local clocks and meant the stronger time-source implementation was not actually wired into QRun block acceptance.

## Implementation

### Public-node configuration

Public-alpha (and the future Mainnet parser contract) now requires all four options:

- `--reference-time-policy-file`: exact signed RTP1 policy document
- `--reference-time-admin-public-key-hex`: pinned policy-admin Ed25519 public key
- `--reference-time-address`: numeric unicast IP:PORT for the TMA1 authority
- `--reference-time-state-file`: durable authority-sequence and policy rollback high-water file

The parser validates all-or-none configuration, absolute paths, an existing parent directory, nonzero/non-weak admin key, and a numeric unicast address with a nonzero port. The high-water state file must be separate from the policy file, node data directory, and External-CAS QCF1 floor. The state store retains an exclusive writer lock and persists policy/authority sequence floors across restarts.

Local loopback testnet can continue to use the operating-system clock; it may also opt into a configured provider. Public modes cannot silently fall back to the local clock.

At startup, the node reads an exact-length policy, validates its signature and Network ID binding, restores the durable rollback floor, builds the persistent authenticated provider and obtains a challenge-bound TMA1 sample before creating the node data directory or binding listeners.

### Runtime timestamp source

- Local transaction mining now derives the candidate block timestamp from a fresh reference-time sample.
- The candidate is forced to be strictly greater than the current canonical timestamp.
- If monotonic advancement would put the candidate more than 120 seconds ahead of the sampled reference time, mining is stopped before spending PoW work.
- Runtime live block submission and peer-synchronized live admission use the same configured provider and obtain their own fresh samples. Historical replay remains clock-free and continues to rely on authenticated archive/checkpoint provenance.
- The policy's optional local-clock sanity bound remains a separate check inside the authenticated provider.

### Session profile binding

The digest of the exact signed RTP1 policy bytes is now included in a domain-separated public-node Profile ID:

`SHA256("QUANTUMZXB-QRUN-V05-TIME-POLICY-BOUND-PROFILE-V1\0" || base_profile_id || policy_digest)`

Consequences:

- All public nodes joining one profile must use the exact same signed policy document.
- A node using a different policy digest derives a different Profile ID and cannot silently form a Noise session with the other profile.
- The policy itself is network-bound by the signed RTP1 verifier.
- Local compatibility profiles without a configured provider retain their previous Profile ID calculation.

The wallet-bound Mainnet manifest now records this expected policy binding, without inventing an epoch or claiming that the authority is a BFT consensus clock.

## Trust and failure model

This provider is an authenticated, signed reference-time authority, not decentralized time consensus. Its signer, operator, reachability and availability are explicit trust dependencies. A compromised, misconfigured or unavailable authority can reject or halt live admission. The Profile ID binding prevents peers from accidentally mixing different policies; it does not make the authority Byzantine-fault-tolerant.

The signed policy admin key and identical RTP1 bytes must be provisioned out of band on every public node. Authority key rotation requires a higher signed policy sequence and a coordinated rollout because the policy digest changes the public Profile ID. The persistent state file must be backed up independently and must not be rolled back together with node data.

## Identity and release boundary

- No Mainnet epoch is selected. The Genesis timestamp in the wallet-bound manifest remains `null`.
- The current wallet-bound Network ID, Genesis ID, state root and External-CAS pins remain the existing legacy unanchored candidate. They are not regenerated by this checkpoint.
- A public profile using an authenticated time policy has a different Profile ID from the legacy profile. Therefore the current frozen Mainnet Profile ID cannot pass a future time-policy-bound Mainnet startup unchanged; the Mainnet identity, Genesis epoch, profile, manifest, cross-language vectors and ECR1/QCF1/QRCP pins must be regenerated as one coordinated identity freeze.
- `QRUN_MAINNET_RELEASE_APPROVED = false` remains unchanged. This does not enable Mainnet, public trading, or a production launch.

**Decision:** use the existing signed reference-time protocol for public-node live admission, bind its exact policy digest into the public session profile, retain OS-clock fallback only for local testnet, and keep Mainnet blocked pending the actual epoch, coordinated identity regeneration, independent authority operations, and multi-host adversarial verification.
