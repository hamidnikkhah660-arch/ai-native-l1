QRun Blockchain: Current Technical Status

Updated 15 November 2026. This page separates completed scoped qualifications from the remaining candidate-release and public-market gates. Passing a test on one path is not presented as qualification of a different path or release profile.

Current source and validation scope

The active candidate worktree is feat/cp0600-bootstrap-sync-startup. It is 12 local commits ahead of its GitHub upstream and contains preserved, uncommitted code and checkpoint changes. PR #194 remains a Draft; the newer CP-0659/0660/0664 market-ingress/runtime work is not yet part of the public default branch.

Completed scoped network qualification

CP-0566C recorded a two-host QFP6/QAP1 qualification across a private NetBird overlay, including authenticated admission and restart/replay checks. This remains valid evidence for that private-overlay candidate path; it is not public-Internet inbound qualification or proof of independently operated public seed hosts.

Current two-source agreement tests

CP-0647–CP-0649 add trust-domain-diverse retry and real Noise history-sync snapshot agreement. The end-to-end two-source fixtures use loopback listeners: consistent source histories pass and divergent histories fail closed. They do not claim public listener or long-running production-node qualification.

Current market execution tests

CP-0659 and the connected Q6QA/Q6TS paths add durable Q6MO order ingress, nonce coordination, replay/anchor enforcement and permissionless runtime wiring. Local focused validation has passed, including 47 market/execution tests and the node-launcher checks recorded in the current engineering session. These are candidate tests, not completed real-value trades.

Active monetary policy — CP-0651

The active candidate policy is a 7,000,000,000 QZXB maximum accounting ceiling, comprising a 1,000,000,000 QZXB owner Genesis allocation and six additional 1B non-circulating accounting labels. The labels are not issued or transferable balances and do not authorize minting. Block subsidy is zero; the candidate producer compensation model is canonical transaction fees only. CP-0651 supersedes the older CP-0437 10B-to-one-owner design and the historical CP-0604 mining allocation model.

Candidate release manifest: exact remaining components

The current candidate release manifest deliberately keeps production_authorized=false and mainnet_status=NOT_AUTHORIZED. It still marks these canonical artifacts as missing:

  1. Final Genesis execution snapshot and owner signature.
  2. Q6GD Genesis descriptor.
  3. Q6CP frozen consensus profile.
  4. Q6PN network profile / pin.
  5. Bootstrap peer set with externally verified public endpoints and Noise public-key fingerprints.

Q6TS is not required for the permissionless full-history release profile. It remains relevant to a separate anchored/checkpoint profile. The manifest also records pending independent consensus, cryptography and economics reviews.

Private overlay versus public Internet ingress

The earlier NetBird two-host qualification is retained as a completed private-overlay test. A separate bounded IPv6 ingress check from the laptop's mobile-hotspot path did not demonstrate unsolicited inbound TCP reachability. The current CP-0656 record therefore does not qualify direct public hosting from that laptop/network. This does not invalidate the earlier NetBird result; the tests answer different questions.

CP-0655 records that two independently administered public seed hosts, their externally verified public endpoints, protected node identities and operator evidence are not yet provisioned in the current release package. Any hosts provisioned outside this workspace must have their endpoint, public-key fingerprint and independent-operator evidence imported and verified before the manifest can be promoted. No endpoint, key, signature or independent review is fabricated.

Market and platform status

No authorized native QZXB Mainnet, verified public circulating balance, live QZXB/USDT market reserve, or exchange trade is claimed. The QX ERC-20 deployment on Ethereum Sepolia is a separate test asset and must not be described as native QZXB.

CoinMarketCap's current tracked-listing guidance calls for a functional website and block explorer plus active public trading with material volume on at least one CMC-tracked exchange; untracked/preview discovery is a distinct category and is not the same as a tracked ranked asset. TradingView does not let users manually add unsupported symbols to its main platform. A custom Advanced Charts integration can use the project's own datafeed, while actual Trading Platform order entry additionally requires a broker backend.

Primary evidence: CP-0647, CP-0648, CP-0649, CP-0651, CP-0652, CP-0655, and CP-0656.

Project status: QRun is experimental public-alpha, not production Mainnet. No public native QZXB market or price is claimed.
