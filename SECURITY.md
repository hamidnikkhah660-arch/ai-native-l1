# Security Policy

## Project status

AI_NATIVE_L1 is an experimental research prototype. It is not a production cryptocurrency, public mainnet, audited security product, or system approved for real funds. Cryptographic and consensus components require independent review. Do not use production assets or valuable keys with this code.

## Reporting a vulnerability

Use the repository's **Security** tab and private vulnerability reporting when available. Please do not include exploit details, private keys, credentials, or sensitive proof-of-concept data in a public issue.

If private reporting is temporarily unavailable, open a minimal public issue that only states that a private security report is needed; omit exploit details and secrets. Maintainers should enable private vulnerability reporting as part of the public repository setup.

## Useful report contents

When safe to share privately, include the affected commit/file, prerequisites, impact, a minimal reproducible case, expected versus actual behavior, and whether the report affects research-only or canonical runtime paths. Do not send live credentials or valuable secrets with a report.

## Handling and disclosure

Reports should be acknowledged, triaged, and handled with a coordinated disclosure approach. No response-time guarantee is made until an independently staffed security process exists. Do not assume that a local test pass or the Gitleaks preflight is a security audit.
