Infrastructure for a more programmable, verifiable digital economy.

QuantumZXB is an independently developed native Layer-1 engineering project bringing together a Rust-based ledger, deterministic state and recovery research, ML-DSA hybrid-signature experiments, and an EVM-compatible smart-contract development track. The long-term vision connects native coin utility, developers and verifiable AI/compute services in one open ecosystem.

One ecosystem vision. Multiple engineering tracks.

The repository contains a broad engineering portfolio spanning native protocol research, cryptographic verification, storage recovery and programmable execution. Each subsystem is developed with explicit interfaces, reproducible tests and a staged integration path.

01 / Native protocol

Ledger, consensus and monetary policy

Rust research components cover proof-of-work and difficulty-adjustment candidates, deterministic state transitions, block validation, chain selection, fork/reorganisation handling, supply accounting and snapshot replay.

02 / Resilient infrastructure

Peer networking and recovery

Authenticated session research, pinned peer identities, bounded ingress and worker queues, archive synchronisation, durable-store models and crash/restart tests support an independently operable network design.

03 / Quantum readiness

ML-DSA and hybrid identity

A real ML-DSA-65 verification adapter is exercised against selected hash-pinned external test vectors. V4 research formats combine Ed25519 and ML-DSA-65 for a staged hybrid-authentication path.

04 / Programmable execution

EVM and Solidity research

A separate revm-based VM lab explores contract execution, gas, storage, receipts and cross-client behaviour. Canonical execution within the native state machine is the next integration track.

05 / Developer tooling

Wallet and asset experiments

A fixed-supply ERC-20 demonstrator and browser deployment console run in EVM testnet/local environments. This historical QX asset is separate from the proposed native QZXB coin.

06 / AI-native direction

Applications and verifiable compute

The roadmap includes developer SDKs, agent identities and payments, provider reputation, verifiable job accounting and AI/compute coordination once each service has measurable interfaces and operating rules.

Research with measurable evidence

State and replay consistency

Regression targets include canonical byte encoding, state-root vectors, branch selection, snapshot validation, replay, reorganisation and crash-recovery models.

Hybrid signature experiments

The selected ML-DSA-65 corpus is hash-pinned and contains expected positive and negative cases. Full default-path hybrid activation and whole-network post-quantum claims require further integration.

Smart-contract interoperability

The isolated EVM lab measures selected execution and state behaviours against another client. Native account, gas, receipt, storage and state-root integration are explicitly scoped in the roadmap.

Architecture principle: every public capability statement maps to source, test vectors or an explicitly labelled roadmap milestone. The research portfolio remains open to independent reproduction and technical collaboration.

Engineering roadmap

The roadmap focuses on integrating the strongest existing components into one deterministic, independently reproducible release path.

Phase 1 - Native protocol

Freeze Genesis, monetary rules and one canonical execution profile; verify issuance and state commitments through the full chain lifecycle.

Phase 2 - Hybrid trust

Integrate the selected ML-DSA/hybrid transaction profile and independently protected recovery trust, then qualify multi-host failure scenarios.

Phase 3 - Native EVM

Freeze the VM fork and gas schedule, integrate accounts/code/storage/receipts, then validate RPC and cross-node contract execution.

Phase 4 - Public devnet

Operate independent nodes with a native wallet, RPC and explorer; test peer churn, upgrades, recovery and real network measurements.

Phase 5 - Release qualification

Reproducible build, dependency provenance, external protocol/cryptography review, remediation and signed release materials.

Phase 6 - Ecosystem & revenue

Deliver sponsor-funded engineering, integration services and developer tools; later pilot verified AI/compute coordination with real service evidence.
